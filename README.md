# 学びのゲーム広場

小学2〜3年生向けの、ブラウザーで遊ぶ学習ゲームです。4つのゲームをホームから選べます。ログインや外部サービスへの回答送信はありません。

## ゲーム

- **九九モンスター図鑑**：1〜9の段をそれぞれ9問練習し、クリアした段のモンスターを集めます（9体）。
- **お買いものクエスト**：6つのおつかいで、品物選び、合計、おつりを練習します。うち2つは、品数または金額のかけ算を含みます。商品は9種類です。
- **漢字探検隊**：2・3年生向けの通常問題が40問（各学年4ステージ、1ステージ5問）あります。別モードの「よみわけ探検」では、同じ漢字の読みを文脈から考える5文に挑戦します。
- **100ます計算**：たし算・ひき算・かけ算を、10問・25ます・100ますから選んで練習します。

## 動作環境

- Node.js 24.18.0
- Bun 1.3.14
- Chromium（ブラウザー検証を行う場合）

上記のバージョンでこのプロジェクトを確認しています。依存関係は `bun.lock` で固定しています。

## 起動と確認

プロジェクトのルートで実行します。

```sh
bun install --frozen-lockfile
bun run dev
```

開発サーバーは `http://localhost:5173` で起動します。変更を配布用ファイルにするには、次を実行します。

```sh
bun run build
```

生成物は `dist/` に出力されます。本番ビルドをローカルで確認する場合は、ビルド後に実行します。

```sh
bun run preview --host 127.0.0.1 --port 4186 --strictPort
```

プレビューは `http://127.0.0.1:4186` で開きます。型検査とユニットテストは次のコマンドです。

```sh
bun run typecheck
bun run test
```

ブラウザーの自動テストは、初回にPlaywright用Chromiumを準備してから実行します。

```sh
bunx playwright install chromium
bun run test:e2e
```

Linuxでブラウザー起動時に共有ライブラリー不足のエラーが出る場合は、Playwright公式のLinux依存関係案内に従ってOS側の依存パッケージを追加してください。`test:e2e` はE2E用TypeScript検査の後にChromiumテストを実行し、テスト用の本番プレビューを起動します。

## 記録とリセット

クリアしたゲームの記録は、現在のブラウザーのlocalStorageに保存されます。保存キーは `manabi-game-hiroba.progress`、形式のバージョンは1です。1ブラウザーにつき1人分を想定しており、別の端末・ブラウザーとは同期しません。ブラウザーのサイトデータを消すと記録も消えます。直近の完了履歴は最大50回分です。

ゲームの途中経過は保存しません。ゲームを離れたりページを再読み込みしたりすると、その回は選択画面からやり直しになります。回答と記録は外部へ送信されず、問題データとイラストはアプリに含まれています。

記録を消すには、ホームの「おうちの人の設定」から「記録をぜんぶ消す」を選び、表示された確認ダイアログで確定します。確認を取り消せば記録は残ります。消去対象はこのアプリの記録キーだけです。localhostと127.0.0.1、または異なるポートで開いたページはブラウザー上で別の保存領域になります。

## 教材・クエストの変更

問題やクエストを変えるときは、データだけでなくステージ構成・完了記録・画面・テストが同じ契約を守ることを確認してください。既存データの差し替えは、以下の件数・ID・形式を保てば行えます。

- **九九**：段ごとの9問と9体の対応を維持します。共通報酬カタログは `src/shared/progress/catalog.ts` にあります。
- **買い物**：`src/apps/shopping/data/products.ts` に商品、`src/apps/shopping/data/quests.ts` にクエストがあります。初版は `shopping:quest-01`〜`shopping:quest-06` の6件で、最初の4件が通常、05が個数のかけ算、06が金額のかけ算です。各クエストの型・計算規則は `src/apps/shopping/domain/types.ts` と `src/apps/shopping/domain/engine.ts` を参照してください。クエストの追加やID変更には、共通カタログ、入力検証、出題画面、完了記録とテストの調整も必要です。
- **通常漢字**：`src/apps/kanji/data/normal.ts` に40問あります。各学年20問を、固定の4ステージへ5問ずつ組み立てます。各問は異なる4択を持ち、文脈に合う答えとヒントを用意します。ステージID・順序・5問という単位を変える場合は、共通カタログ、`NORMAL_STAGES` の構成、画面、検証処理、テストを一緒に更新します。
- **よみわけ**：`src/apps/kanji/data/readingDifference.ts` の各文は、明示的な `segments` 上に回答箇所を2つ持ちます。2つの対象は同じ漢字で、異なるひらがなの読みを持ち、それぞれ異なる4択と文脈ヒントを備えます。IDで対象箇所と選択肢・答えを結び、出題順を保ちます。仕様上1回は5文です。将来文の候補を増やす場合も、1回に選ぶ文は5つのままにします。現行の取得関数と内容検証は候補をちょうど5文とするため、候補を増やす作業では `getReadingDifferenceStage` 相当の取得処理、検証処理、テストを更新して、重複なしで5文を選ぶことを確認します。専用宝物と完了記録も合わせて確認します。
- **漢字の学年確認**：対象字の配当学年と教材確認の根拠は[漢字教材の内容確認記録](docs/reviews/learning-content.md)にあります。教材を変えたら記録も見直してください。

ステージ・クエストの追加はデータへの追記だけでは完了しません。既存のステージ・クエスト・報酬IDは、保存済みの達成記録を引き継ぐため維持してください。`src/shared/progress/catalog.ts`、型と検証、ステージ生成、画面、完了処理、テストでID・問題数・報酬の整合を確認してください。共通カタログは初版の全33エントリーを管理しています。

## 対象範囲と確認上の制限

本アプリは学習効果や学年範囲全体の網羅を保証するものではありません。ログイン、複数プロフィール、端末間同期、途中からの再開、ランキング、実行時のAI問題生成はありません。保存はブラウザーとオリジンごとに分かれ、複数タブから同時に書き込む場合の競合解決は行いません。

ブラウザー確認はPlaywright同梱Chromiumと複数の画面幅で行っています。実機、Chromium以外のブラウザー、ネットワーク公開環境の互換性は確認していません。実行した検証と本番プレビューの記録は[検証記録](docs/reviews/validation.md)を参照してください。
